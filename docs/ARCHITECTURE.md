# Прямое извлечение моделью — v4

`Upload → input_file/input_image → Responses API → DocumentAnswer → проверки → JSON/UI/SQLite`

Рабочий код — `backend/model_document.py`. `pipeline.process_document` вызывает только `extract_model_document`. Ни `read_document`, ни `extract_rules`, ни `extract_universal` в этом пути не вызываются. DOCX и Excel передаются исходными файлами. Изображения преобразуются в поддерживаемую кодировку без OCR.

## Разделение кода

| Модуль | Ответственность |
| --- | --- |
| `backend/document_input.py` | Упаковка исходных файлов и преобразование изображений без извлечения данных. |
| `backend/document_prompt.py` | Инструкция модели. |
| `backend/document_models.py`, `backend/proposal_models.py` | Контракты ответа модели и сохраняемого КП. |
| `backend/model_document.py` | Вызов модели, согласованность её ссылок и проверка арифметики. |
| `backend/openai_client.py`, `backend/errors.py` | HTTP-пул, строгая JSON-схема, повторы ответов 429/5xx и безопасные ошибки провайдера. |
| `backend/pipeline.py` | Очередь, процессы, тайм-ауты, кеш и перенос ошибок до HTTP-маршрута. |
| `backend/annotation_models.py`, `backend/source_catalog.py` | Контракты ручной разметки и работа с сохранёнными ячейками. |
| `backend/semantic_contracts.py`, `backend/numeric_values.py` | Общие структуры старых данных и проверка чисел без загрузки парсеров. |
| `src/lib/uploadProcessing.ts` | Чтение загрузок, ограничение параллелизма и нормализация ошибок. |
| `src/components/UploadResults.tsx`, `src/types/extraction.ts` | Представление результатов и общие типы frontend. |

При обычном импорте `backend.main` не загружаются `extraction`, `rules`, `vision`, `universal`, `local_model` и Office-парсеры. Экспорт старой разметки и обучение используют отложенные импорты; совместимые переэкспорты сохранены. Это проверяется отдельным тестом в новом процессе.

## Ошибки и повтор загрузки

Ошибка провайдера сохраняет `code`, `stage`, `retryable` и HTTP-статус при передаче из worker. Сброс TLS возвращается как HTTP 503, тайм-аут транспорта — 504, ограничение частоты — 429. Отклонённый запрос API отличается от ошибки соединения; текст ответа провайдера и документы не попадают в публичные сообщения.

Строгая JSON-схема требует все ключи, сохраняя объявленные типы: пустые списки возвращаются как `[]`, необязательные числовые значения допускают `null`. Ранее добавленная возможность `null` для списков удалена, поскольку она противоречила контрактам Pydantic.

При полном отказе интерфейс показывает только результаты загрузок. При частичном успехе повтор отправляет неудачные файлы, сохраняя успешные результаты и ручные исправления. Подробности и учёт расхода раскрываются по запросу; отсутствие статистики не превращается в нулевую стоимость.

Модель возвращает готовый `ProposalData`, транскрипцию `cells`, цитаты `evidence`, `complete` и `warnings`. Общая схема извлечения и сохранения находится в `backend/proposal_models.py`. Код проверяет структуру и арифметику; значения не заменяет и не вычисляет отсутствующие числа.

Все модельные цитаты имеют `verifiedInSource=false`. Проверка ссылки внутри транскрипции проверяет согласованность ответа, а не совпадение с оригиналом. Независимого покрытия строк нет: `coverageComplete=false`; `modelReportedComplete` — самооценка модели. UI требует сверки по оригиналу.

Новые загрузки разметки используют тот же API-путь. Роли таблиц подтверждает человек; старые записи и экспорт сохранены. Legacy-модули оставлены для старых данных и экспериментов.

Ограничения input_file: DOCX — текст без изображений, spreadsheets — первые 1000 строк листа. [Документация](https://developers.openai.com/api/docs/guides/file-inputs). Успешный HTTP-ответ не доказывает полноту чтения.

Сохранены workers, очередь, deadlines/retries, usage, стоимость, SQLite и idempotency. Cache namespace v4 отделён от v3. Кешируются только согласованные завершённые ответы с цитатами; результат остаётся модельным и требует ручной сверки.
