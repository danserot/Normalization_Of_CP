# ReadDocument

ReadDocument извлекает реквизиты и позиции из коммерческих предложений, показывает источники распознанных значений, помогает разрешить расхождения между файлами и сохраняет проверенный результат.

## Возможности

- Загрузка нескольких PDF, DOCX, XLSX, XLS, CSV, TSV, TXT, JSON, PNG, JPG и WEBP файлов до 25 МБ каждый.
- Предварительное OCR сканов через Tesseract с русским и английским языками, после чего текст структурируется компактной Qwen 2.5 3B.
- Выбор одной модели или последовательное сравнение локальных text-моделей.
- Извлечение текста из PDF/DOCX и OCR сканов/изображений через Tesseract; длинный текст делится на части, чтобы модель не теряла конец документа.
- Сравнение количества найденных полей, позиций, итоговой суммы, времени и уверенности каждой модели.
- Локальный разбор таблиц и текстовых файлов в браузере; PDF/DOCX также используют его как запасной вариант, если AI API недоступен.
- Сводка нескольких файлов с явным выбором при конфликте реквизитов и предупреждениями о возможных повторных позициях.
- Ручное редактирование, проверка обязательных полей и сравнение итоговой суммы с суммой из документа.
- Экспорт результата в JSON и CSV.
- Сохранение подтвержденных данных в SQLite с ключом идемпотентности и получением сохраненной записи по ID.

Распознавание не считается подтверждением: проверьте значения и цитаты источника. OCR использует только видимые данные и может ошибаться. Если у поля нет точного совпадения в извлеченном текстовом слое, интерфейс помечает источник как требующий проверки.

## Запуск через Docker

```powershell
docker compose up --build
```

Откройте `http://localhost:8080`. В безопасной конфигурации Tesseract сначала переводит сканы в текст, а Ollama загружает только Qwen 2.5 3B. Для Ollama задан лимит контейнера 3 ГБ и одна параллельная задача. Результаты SQLite хранятся в volume `proposal_data`, модели — в `ollama_data`.

Ollama опубликована только на loopback `127.0.0.1:11434`. API доступен интерфейсу через Nginx и не публикует порт напрямую.

Остановка:

```powershell
docker compose down
```

Чтобы удалить также данные модели и сохраненные предложения, отдельно выполните `docker compose down --volumes`.

## Запуск для разработки

Установите и запустите локальную модель:

```powershell
ollama pull qwen2.5:3b
ollama serve
```

В отдельном терминале установите и запустите API:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r backend\requirements.txt
uvicorn backend.main:app --reload --port 8000
```

В третьем терминале запустите интерфейс:

```powershell
npm install
npm run dev
```

Интерфейс доступен на `http://localhost:5173`, API проксируется через Vite. SQLite файл по умолчанию создаётся в `backend/data/readdocument.sqlite3`; путь и список разрешённых моделей можно изменить переменными `DATABASE_PATH`, `OLLAMA_MODEL`, `OLLAMA_MODELS` и `OLLAMA_URL`. Для OCR доступны `TESSERACT_LANG` и `TESSERACT_CONFIG`; по умолчанию используются `rus+eng` и `--oem 1 --psm 6 -c preserve_interword_spaces=1`.

## API

- `GET /api/health` — состояние API и имя модели.
- `GET /api/models` — разрешённые модели и статус их загрузки в Ollama.
- `POST /api/extract` — загрузка и распознавание файла (multipart поле `file`).

Для экономии памяти Ollama держит загруженной не более одной модели, а backend сериализует inference-задачи и выгружает модель после каждого полного прохода. PDF/DOCX с текстовым слоем не проходят OCR; для сканов Tesseract обрабатывает максимум 4 страницы без текстового слоя по одной за раз. В Ollama отправляется только текст, без изображений. Большие модели можно включить через `.env`, но они уже не гарантируют предел 2–3 ГБ.
- `POST /api/proposals` — сохранение подтвержденного предложения. Необязательный заголовок `Idempotency-Key` должен содержать UUID; повтор с тем же ключом возвращает исходный ID.
- `GET /api/proposals/{id}` — чтение сохраненного предложения по UUID.
- `GET /api/session`, `POST /api/login`, `POST /api/logout` — состояние сессии и вход по паролю.

## Безопасность и размещение

Для Docker можно включить парольную защиту: скопируйте `.env.example` в `.env`, задайте длинные случайные `APP_PASSWORD` и `APP_SECRET`. Файл `.env` исключен из Git. `APP_SECRET` подписывает HttpOnly cookie сессии на 8 часов. Без `APP_PASSWORD` аутентификация выключена, что удобно для локального использования. При публикации настройте HTTPS и установите `COOKIE_SECURE=true`; используйте reverse proxy с ограничением частоты запросов к входу. Сейчас поддерживается один общий пароль, без отдельных учетных записей и разграничения доступа между пользователями.

Исходные файлы обрабатываются в памяти процесса и не сохраняются в базе; в SQLite остаются только подтвержденный JSON и сведения об источниках. Не отправляйте документы в общедоступный Ollama endpoint.
