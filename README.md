# ReadDocument — локальное извлечение данных из коммерческих предложений

PDF, DOCX, XLSX, XLS, CSV, TSV, TXT, JSON, PNG, JPG/JPEG и WEBP проходят один backend-конвейер. Обработка выполняется на CPU. Исходные файлы, текст и результат не передаются внешним сервисам. Ключи внешних API не нужны; облачного fallback нет. В браузере нет внешних шрифтов или моделей.

ReadDocument преобразует разнородные коммерческие предложения в единую структуру: реквизиты документа, сведения о клиенте и поставщике, условия, позиции, цены и итог. Для каждого найденного значения сохраняется ссылка на исходную страницу, лист, строку или ячейку. Система намеренно оставляет сомнительные значения пустыми и показывает предупреждение вместо того, чтобы угадывать данные.

> **Важно:** результат распознавания — черновик. Перед сохранением оператор должен сверить предупреждения, OCR-данные, суммы и реквизиты с оригиналом документа.

## Что умеет система

- читает текстовые документы, таблицы, PDF и изображения;
- запускает Tesseract только для изображений и страниц PDF без пригодного текстового слоя;
- находит реквизиты по явным русским, английским и части казахских меток;
- распознаёт таблицы позиций при наличии понятных заголовков колонок;
- сохраняет доказательство для каждого значения в `metadata.fieldEvidence`;
- обнаруживает конфликты, неоднозначные числа, расхождения в суммах и пропущенные поля;
- позволяет исправить результат, подтвердить его, сохранить в SQLite и выгрузить JSON/CSV;
- может работать без модели: детерминированные правила и OCR остаются доступными.

Система не выполняет электронную подпись, бухгалтерскую проводку, оплату, автоматическое согласование или юридическую проверку документа. Она также не гарантирует правильность OCR и не подменяет проверку оператором.

## Архитектура и поток данных

```text
Браузер (React/Vite)
        │ файл, выбранный пользователем
        ▼
Nginx :8080 ──► FastAPI :8000 ──► отдельный worker-процесс
                                      │
                                      ├─ чтение PDF/Office/текста/изображения
                                      ├─ Tesseract для сканов
                                      ├─ детерминированные правила
                                      ├─ Qwen через llama.cpp :8081 (необязательно)
                                      └─ валидация и доказательства
        ▲
        └──────── результат, предупреждения, источники

Подтверждённый результат ──► SQLite volume `proposal_data`
```

Backend обрабатывает один документ за раз. Сам файл постоянно не сохраняется: в SQLite попадают только подтверждённая структура и переданные вместе с ней метаданные источников. Контейнер модели не имеет отдельного внешнего порта и разделяет сетевое пространство backend.

## Первоначальная установка

Нужны Docker Desktop / Docker Compose и Python 3.11+ для однократной загрузки весов. Следующие команды требуют сети только для установки зависимостей, образов и весов:

```powershell
# Для нового окружения; существующий .env не перезаписывайте.
Copy-Item .env.example .env
python scripts/setup_model.py
docker compose build
docker compose --profile model pull model
docker compose --profile model up -d --no-build
```

Windows с Python Launcher: вместо `python` можно использовать `py -3.13`.
Интерфейс: http://localhost:8080. Проверка: `GET /api/health` — `provider: local`, `configured: true`, если модель загружена.

Используется [Qwen2.5-1.5B-Instruct GGUF Q4_K_M](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF) через [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). Файл весов: **1 117 320 736 байт** (это размер на диске, не RAM). Скрипт фиксирует revision и SHA-256, проверяет существующий файл и не скачивает его повторно. Образ llama.cpp закреплён digest в Compose. Веса лежат в игнорируемом каталоге `models/`, подключаются read-only, модель загружается один раз при запуске своего контейнера.

Параметры: CPU, `-ngl 0`, контекст `-c 8192`, один слот `-np 1`, четыре потока `-t 4`, batch/microbatch `128`, temperature `0`, максимум `1800` выходных токенов. Модель возвращает JSON Schema с реквизитами и схемами таблиц. Код проверяет идентификаторы, цитаты, заголовки компонентов и читает все строки выбранных диапазонов. Скорость и качество ограничены установленной моделью 1.5B: её ответ не считается подтверждением правильности данных.

## Как используются правила, OCR и модель

Компоненты выполняются в фиксированном порядке:

1. Парсер проверяет расширение, сигнатуру и ресурсные лимиты файла.
2. Из документа создаются нормализованные ячейки с координатами источника.
3. Для сканов Tesseract извлекает текст; текстовые страницы PDF повторно через OCR не проходят.
4. Модель видит компактный каталог блоков с образцами заголовков и строк и определяет реквизиты, диапазоны таблиц, роли колонок и продолжения страниц без списка шаблонов поставщиков.
5. Код читает все строки по выбранным схемам, сохраняет компоненты стоимости в `items[].components`, нестандартные поля в `additionalFields`, проверяет источники. Вычисленная сумма компонентов помечается `method=calculated` с формулой и источниками; она не выдаётся за цитату.
6. Повторные запросы модели проходят все исходные строки порциями. Пропуски, нечисловые значения и арифметические расхождения показываются оператору. При подключённой зрительной модели сложные страницы дополнительно проверяются по изображениям.
7. Валидатор проверяет даты, обязательные данные позиции, арифметику строки и общий итог.

| Компонент | Для чего используется | Чего не делает |
|---|---|---|
| Детерминированные правила | Только резервный разбор при недоступности универсальной модели | Не гарантируют обработку неизвестной структуры |
| Tesseract | Текст и координаты на изображениях и сканированных страницах | Не подтверждает смысл или правильность текста |
| Qwen2.5 1.5B | Определение структуры, колонок, компонентов стоимости, реквизитов и повторная проверка | Не имеет зрительных возможностей и не гарантирует правильную интерпретацию |
| Валидатор | Даты, `количество × цена`, итог с явными НДС/скидкой/доставкой | Не интерпретирует сложные налоговые и договорные условия |

### Правила безопасности модели

- endpoint зафиксирован в коде как `http://127.0.0.1:8081` и не перенаправляется на произвольный URL;
- HTTP-клиент игнорирует proxy-переменные, запрещает redirects и ограничен остатком общего времени обработки;
- первоначальный запрос ограничен 24 000 символами; при превышении явно возвращается резервный режим;
- в запрос передаются идентификатор и текст ячейки, а не полный исходный файл;
- JSON Schema ограничивает размеры массивов и диапазоны колонок; ссылки проверяются кодом;
- значение должно буквально присутствовать в заявленной ячейке;
- конфликтующие цитаты сохраняются в доказательствах и отмечаются предупреждениями;
- модель назначает роли колонок позиций; числа читает и проверяет код;
- неподтверждённый или некорректный ответ отклоняется, а результат правил сохраняется;
- текст документа считается данными, а не инструкцией для модели.

### Когда запускать без модели

Установите `LOCAL_MODEL_ENABLED=false`, если модель не нужна, отсутствует файл GGUF или важнее минимальное потребление памяти. OCR, правила, проверка и сохранение продолжат работать. В интерфейсе появится предупреждение, что использовались только локальные правила.

## Настройки окружения

Создайте `.env` из примера и не добавляйте его в Git:

```powershell
Copy-Item .env.example .env
```

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `LOCAL_MODEL_ENABLED` | `true` | Разрешить обращения backend к локальному llama.cpp |
| `LOCAL_VISION_ENABLED` | `false` | Дополнительная проверка изображений локальным multimodal llama.cpp на `127.0.0.1:8082`, alias `local` |
| `EXTRACTION_TIMEOUT_SECONDS` | `480` | Общий бюджет обработки; разрешено 30–600 секунд |
| `TESSERACT_LANG` | `rus+eng` | Языки OCR; для казахского текста используйте `rus+eng+kaz` |
| `APP_PASSWORD` | пусто | Включить пароль для интерфейса и защищённых API |
| `APP_SECRET` | случайный при старте | Ключ подписи cookie; в постоянном окружении задайте стабильную длинную случайную строку |
| `COOKIE_SECURE` | `false` | Передавать session cookie только по HTTPS; в production задайте `true` |

`DATABASE_PATH` внутри Compose уже задан как `/data/readdocument.sqlite3`. Сессия действует 8 часов, cookie имеет флаги `HttpOnly` и `SameSite=Strict`. Если `APP_SECRET` не задан, после перезапуска backend существующие сессии перестанут быть действительными.

## Работа полностью офлайн

После первоначальной установки отключите интернет и запускайте без сборки и pull:

```powershell
docker compose --profile model up -d --no-build --pull never
```

Backend подключён только к Docker-сети `offline` с `internal: true`. Модель использует его сетевое пространство и слушает строго `127.0.0.1:8081`; endpoint не задаётся произвольным URL. HTTP-клиент игнорирует proxy-переменные и не следует перенаправлениям. Nginx дополнительно имеет сеть для публикации интерфейса на `127.0.0.1:8080`; модель и backend в эту сеть не включены.

Без модели:

```powershell
docker compose stop model
docker compose up -d --no-build --pull never frontend backend
```

Работают локальные правила и OCR; результат содержит видимое предупреждение об отсутствии модели. Для постоянного отключения задайте `LOCAL_MODEL_ENABLED=false` в `.env` и пересоздайте backend. Автоматической загрузки весов при старте нет.

SQLite хранится в volume `proposal_data`; `docker compose down` сохраняет данные. Исходные файлы не сохраняются приложением постоянно; multipart может временно использовать локальный диск. Подтверждённые результаты, исходные цитаты и координаты остаются в SQLite. `.env` и файлы базы исключены из Git и Docker build context.

## Инструкция пользователя

1. Откройте <http://localhost:8080> и, если включена защита, введите `APP_PASSWORD`.
2. Оставьте режим «Локальное извлечение». Если модель выключена или не запущена, документ всё равно будет обработан правилами.
3. Выберите один или несколько файлов поддерживаемого формата. Они обрабатываются последовательно.
4. Дождитесь результата и сначала прочитайте все предупреждения.
5. Раскройте доказательства у полей: проверьте имя файла, страницу/лист, строку, метод и цитату.
6. Особо проверьте значения с методом `ocr` или `model`, низкой уверенностью и текстом «требуется подтверждение».
7. Сверьте количество, цену, сумму строки, валюту, НДС, скидку, доставку и общий итог.
8. При объединении нескольких файлов разрешите показанные конфликты и выберите правильный вариант.
9. Нажмите «Изменить данные», если нужно исправить результат. Ручное значение считается решением оператора и не получает доказательство от другой строки.
10. Нажмите «Подтвердить данные», затем «Сохранить на сервере». До подтверждения сохранение недоступно.

JSON и CSV можно скачать до серверного сохранения. При загрузке нового набора файлов старый результат очищается, чтобы пользователь не работал с устаревшими данными.

## Правила извлечения и проверки

### Реквизиты

Система ищет явные метки: название, клиент/заказчик/покупатель, контакт, срок действия, поставщик, валюта, НДС, скидка, доставка, условия оплаты и поставки, гарантия, номер, дата и итог документа. Метка и значение могут находиться в одной ячейке (`Клиент: Альфа`) или в соседних ячейках строки.

Если один реквизит встречается с разными значениями, оба варианта сохраняются как доказательства, а пользователь получает предупреждение о конфликте. Модель не имеет права перезаписать значение, уже найденное правилами.

### Позиции

Строки считаются позициями только после распознанной строки заголовков. Обязателен столбец наименования и хотя бы один из столбцов количества, цены или суммы. Поддерживаются перестановки колонок. Строки `ИТОГО`, НДС, скидка, доставка, подпись, примечание и другие служебные строки не становятся товарными позициями.

Для сохранения позиция должна иметь непустое наименование, положительное количество и неотрицательную цену. Во время извлечения неизвестные количество и цена остаются `null`, чтобы оператор мог заполнить их вручную.

### Числа и суммы

- поддерживаются `1 234,56`, `1.234,56`, `1,234.56` и `1234.56`;
- валютные обозначения RUB, USD, EUR, KZT, TRY, руб., тенге, ₽, ₸, $, € удаляются перед разбором числа;
- `1,234` и `1.234` считаются неоднозначными и не преобразуются автоматически;
- дата, SKU, `NaN`, бесконечность, логическое значение и текст с посторонними символами не становятся ценой;
- отрицательные значения позиции отклоняются;
- сумма строки сравнивается с `количество × цена` с допуском 0,02;
- общий итог сравнивается с суммой позиций и вариантами с явно указанными процентными НДС, скидкой и числовой доставкой;
- сложные налоговые формулировки всегда требуют ручной проверки.

### Даты, доказательства и уверенность

Даты вида `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ` и `ДД-ММ-ГГГГ` проверяются как календарные. Некорректная дата не скрывается, но помечается предупреждением.

`metadata.sourceCells` содержит нормализованные ячейки источника. `metadata.fieldEvidence` связывает результат с точной цитатой. Уверенность `0.95` означает детерминированное извлечение из текстового источника; `0.65` используется для OCR и выбора модели. Это эвристический индикатор метода, а не статистическая вероятность правильности.

## Форматы документов

- PDF: текст и координаты слов, табличные ячейки; страницы без пригодного текста проходят OCR последовательно. В смешанном PDF текстовые страницы не запускают OCR.
- DOCX: абзацы и таблицы в исходном порядке, реквизиты вне таблиц, текст колонтитулов.
- XLSX/XLS: все листы, заголовки по именам, любой порядок колонок, отдельные цена и сумма строки. Итоговые и служебные строки исключаются. Формулы XLSX читаются из сохранённого Excel-кэша; отсутствующий кэш остаётся пустым.
- CSV/TSV: разделители `;`, табуляция, запятая и `|`; UTF-8/BOM, UTF-16/BOM и Windows-1251. Для значений с запятой CSV должен использовать кавычки или другой разделитель.
- JSON: объект с ключами существующих полей и массивом `items`, объект `proposal` либо массив объектов-позиций. Неизвестные вложенные структуры возвращают предупреждение.
- PNG/JPG/WEBP и сканы: Tesseract, EXIF-поворот, определение ориентации, ограниченное масштабирование, PSM 3/6 по форме страницы, восстановление строк по координатам.

## OCR-языки

По умолчанию `TESSERACT_LANG=rus+eng`. В Docker также установлен `kaz`. Для казахских документов установите `TESSERACT_LANG=rus+eng+kaz` в `.env` и пересоздайте backend. На синтетическом тесте без `kaz` текст «Қазақ Өнім / Әділ Ұйым» искажался, с `kaz` восстановился точно. Казахские/смешанные документы всё равно требуют проверки; полнота казахских меток не заявляется.

## Ограничения ресурсов

25 МиБ на файл; 50 страниц PDF; 20 млн исходных пикселей и сторона OCR до 2400 px; 200 000 символов; 30 000 ячеек; 30 листов; 10 000 строк / 100 колонок на лист; 2000 позиций; распакованный Office-архив до 80 МиБ. Превышение завершается понятной ошибкой без молчаливого обрезания.

Одна обработка на backend, повторный параллельный запрос получает HTTP 429. OCR до 35 с, определение ориентации до 8 с, запрос модели до 180 с с учётом оставшегося общего бюджета. Весь рабочий процесс по умолчанию ограничен 480 с; при зависании завершается вместе с OCR-потомками. Следующий запрос создаёт новый процесс. Если проверены не все порции, `metadata.verification.reviewCompleted=false` и интерфейс показывает предупреждение. Запускайте **один uvicorn worker**, без реплик при этих лимитах.

`metadata.verification` содержит режим (`model` или `fallback`), число проверенных порций, незадействованные строки, статус визуального прохода и замечания. `coverageComplete` означает завершение предусмотренных проверок без найденных незадействованных числовых строк, а не доказательство смысловой точности. Зрительный проход проверяет структуру по изображениям, но не принимает новые числа без текстовой цитаты: повреждённый OCR требует сверки оригинала. Отдельная зрительная модель и её веса в поставку не входят.

Лимиты контейнеров без swap: backend 768 МиБ, модель 1900 МиБ, nginx 128 МиБ. Сумма 2796 МиБ ≈ 2,93 ГБ. Это защитные ограничения; реальные измерения описаны в [VERIFICATION.md](VERIFICATION.md). Браузер пользователя и Docker VM считаются отдельно от контейнерного приложения.

## Тесты и измерение RAM

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r backend/requirements-test.txt
.venv/Scripts/python -m backend.tests.fixtures
.venv/Scripts/python -m pytest backend/tests -q
# Полный набор с реальным Tesseract и без сети:
docker build -f backend/Dockerfile.test -t readdocument-tests .

# Работающее приложение + Qwen, синтетические HTTP-запросы:
.venv/Scripts/python scripts/benchmark.py
npm run lint

```

Набор вымышленных КП в 12 форматах, эталон полей и команда проверки качества находятся в [examples/mock_kp/README.md](examples/mock_kp/README.md). Аудит сверяет 22 значения на каждом формате и наличие ссылки на исходную ячейку; сканы проверяются в контейнере с Tesseract.

На Linux используйте `.venv/bin/python`. Генератор создаёт репрезентативные документы в `test-results/fixtures`. Benchmark сохраняет `test-results/memory.json` и ответы API, проверяет заполнение полей, сохранение, чтение и идемпотентность. Он измеряет `memory.current` всех трёх контейнеров с целевым шагом 50 мс и точные накопленные `memory.peak` ядра; OCR-процессы и mmap модели включены. Сумма индивидуальных пиков — консервативная верхняя оценка общего пика. Не используйте размер GGUF или только RSS backend вместо этого измерения.

## Локальная разработка

Установите Tesseract и языки отдельно, зависимости из `backend/requirements.txt`, затем:

```powershell
.venv/Scripts/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
npm ci
npm run dev
```

Для модели вне Docker запустите установленный llama-server с параметрами из Compose на `127.0.0.1:8081`. Vite проксирует `/api` на порт 8000. Docker обеспечивает явные ограничения памяти и сети; при запуске процессов напрямую эти ограничения должен задать оператор. `.env` в таком режиме сам не загружается — задайте переменные окружения явно.

## API

| Метод и путь | Авторизация | Назначение |
|---|---|---|
| `GET /api/health` | нет | Состояние API, SQLite, модели и флаг `busy` |
| `GET /api/models` | да | Доступные способы извлечения |
| `POST /api/extract` | да | Multipart: `file` и необязательный `models=["local"]` |
| `POST /api/proposals` | да | Сохранить подтверждённое предложение |
| `GET /api/proposals/{id}` | да | Получить сохранённое предложение по UUID |
| `GET /api/session` | нет | Состояние текущей сессии и необходимость пароля |
| `POST /api/login` | нет | Вход с JSON `{"password":"..."}` |
| `POST /api/logout` | нет | Завершение сессии |

Для сохранения положительное количество и неотрицательная цена обязательны; отсутствующий документный итог допустим. `Idempotency-Key` — UUID. Парольная защита включается через `APP_PASSWORD` и `APP_SECRET`; для HTTPS задайте `COOKIE_SECURE=true`. По умолчанию интерфейс доступен только с этого компьютера.

Пример проверки и извлечения без включённого `APP_PASSWORD`:

```powershell
curl.exe http://localhost:8080/api/health
curl.exe -X POST http://localhost:8080/api/extract -F "file=@example.pdf" -F 'models=["local"]'
```

Если пароль включён, сначала вызовите `/api/login` с cookie-файлом, а затем передайте тот же файл через `curl.exe -b`. Браузер делает это автоматически.

Основные ответы с ошибками:

| Код | Причина |
|---:|---|
| `400` | Некорректный `Idempotency-Key` |
| `401` | Требуется вход |
| `413` | Файл больше 25 МиБ |
| `415` | Неподдерживаемое расширение |
| `422` | Неверный файл, превышение внутренних лимитов или невалидная структура сохранения |
| `429` | Backend уже обрабатывает другой документ; повторить не раньше чем через 5 секунд |
| `500` | Ошибка сохранения в SQLite |

## Диагностика

Проверить состояние контейнеров и последние сообщения:

```powershell
docker compose --profile model ps
docker compose logs --tail 100 backend model frontend
Invoke-RestMethod http://localhost:8080/api/health
```

- `configured: false`: модель выключена, ещё запускается, не найден GGUF или недоступен llama.cpp. Правила и OCR продолжат работать.
- HTTP 429: дождитесь завершения текущего документа. Текущая архитектура не содержит очереди задач.
- «Не установлены языки Tesseract»: проверьте `TESSERACT_LANG` и наличие соответствующего языкового пакета в окружении.
- Пустые формулы XLSX: откройте файл в Excel/LibreOffice, пересчитайте и сохраните его, чтобы обновился кэш значений.
- Неверный текст CSV/TXT: сохраните файл как UTF-8, UTF-16 или Windows-1251.
- Ошибка после 180 секунд: уменьшите документ или разделите его; worker и дочерние OCR-процессы будут остановлены автоматически.
- Вход сбрасывается после перезапуска: задайте постоянный `APP_SECRET`.

Для полного списка выполненных проверок, измерений памяти и честных границ верификации см. [VERIFICATION.md](VERIFICATION.md).
