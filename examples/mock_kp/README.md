# Синтетические коммерческие предложения для проверки извлечения

В каталоге один вымышленный КП в 12 форматах: CSV, DOCX, JPG, JSON, PDF с текстовым слоем, PNG, TSV, TXT, WEBP, XLS, XLSX и сканированный PDF. В нём два товара, переставленные столбцы таблицы, реквизиты, срок действия, условия оплаты, валюта и итог. Реальных персональных данных нет.

`ambiguous.txt` — отдельный КП для проверки локальной модели: клиент записан как «Для ...», поставщик как «От ...». Правила оставляют эти поля пустыми, а запущенный Qwen может определить роли. Принятый ответ должен сохранить точную цитату и предупреждение о ручном подтверждении в `fieldEvidence`.

`expected.json` задаёт эталон формы: 12 реквизитов и пять значений для каждой из двух позиций, всего 22 значения. `audit.json` — прогон на хосте, `audit-http.json` — последний прогон через локальный HTTP API. Отчёты перезаписываются при повторном запуске и отражают именно то окружение, где был выполнен аудит.

Запуск из корня проекта:

```powershell
.venv/Scripts/python -m scripts.quality_audit
.venv/Scripts/python -m scripts.quality_audit http://127.0.0.1:8000
```

Первый вызов пересоздаёт мок-файлы и проверяет их напрямую. Второй загружает те же файлы через `POST /api/extract`. Для изображений и сканированного PDF необходим Tesseract с языками `rus+eng`; если его нет, отчёт отмечает эти форматы как `unavailable`, а не как успешные. В контейнере проекта OCR-языки уже установлены.

Проверка полного регрессионного набора в контейнере без сети:

```powershell
docker build -f backend/Dockerfile.test -t readdocument-tests .
docker run --rm --network none readdocument-tests
```

Метрика `fields_correct` сравнивает значения с эталоном. `missing_evidence` показывает поля без привязки к исходной ячейке. `pass` означает точное совпадение всех 22 значений и наличие источника для каждого. Эта синтетическая выборка проверяет регрессии, но не измеряет точность на произвольных реальных КП.
